# StreetZim app state machines

This inventory covers the public map catalog, the Drive picker and offline/preview viewer, the browser language builder and its delivery services, and the supported CLI build and download entry points. It follows state that survives an event, a request, an await, or a process restart. The tables collapse transient implementation steps that share the same transition rules. “Explicit” means the code names a state in a protocol, status field, or persisted record. “Implicit” means the state is derived from flags, a promise, a cache, a handle, or the existence of an artifact.

## Transitions that went wrong, most harmful first

Each row names a transition that once went wrong, how, and the rule that now holds. The tables below describe the current code.

| Transition | What went wrong | Rule and regression coverage |
| --- | --- | --- |
| **Keep Drive's selection coherent** | **Wrong map data.** Serve a buffered path from A and suspend `readEntry`. Select B and request the same path before A's read settles. The path-only in-flight map gives B the bytes of A. The controlled test observed `'A' !== 'B'`. In the original picker protocol, a slow `set-zim` could commit after a later Clear. A status request could also combine A's reader with the page's newly committed record for B. A failed persistent replacement cleared the session metadata before its write succeeded, and a failed delete could leave the old durable map behind a reported session success. A preview could also accept B’s bytes at the same URL after opening A because later ranges ignored the saved validators. The range test previously resolved instead of rejecting. | In-flight reads are keyed by reader and normalized path. The picker and worker exchange an IndexedDB revision, the worker guards superseded selections, and status reads a record and reader together. Remote range reads retire the source on a conflicting validator or total. [sw_state_js.test.mjs](../tests/sw_state_js.test.mjs) covers a cross-map read, Clear during validation, the page-commit/reload boundary, failed writes, lazy reopen on retry, and a changed remote source. [test_picker.mjs](../tests/test_picker.mjs) covers Clear during file validation across the actual picker and IndexedDB boundary. |
| **Keep a resumed CLI download on one source version** | **Wrong or unusable input artifact.** A partial transfer is stamped from HEAD. An origin can change between HEAD and GET, or return a 206 with the requested start and an inconsistent end or total. The old append gate checked only the start, so a generic MBTiles URL without a published checksum could pass the final length and SQLite-header checks with bytes from two versions. A file cut off before the SQLite magic could also survive under a matching stamp, then throw on every resume before the cleanup handler. | Check the response validator when provided and require an exact resume interval. Discard a partial with an invalid prefix before retrying. [test_mbtiles_download.py](../tests/test_mbtiles_download.py) exercises the HTTP and persisted-file paths. |
| **Retire stale viewer intent** | **Wrong endpoints or revived results.** While graph loading is pending, pick a route endpoint and click Clear. The old polling callback can call the endpoint setter after the graph arrives. Its sequence number was allocated on replay, after Clear. In route and map typeahead and the Find page’s near-place input, deleting or dismissing the input while an older search runs could leave its generation current long enough to repopulate the results. | Claim endpoint ownership before queueing a graph replay. Invalidate result generations on edit and dismissal, cancel debounce work, and restrict selection to live rows. A blur only hides the route picker's list: a running lookup finishes, and its answer shows on refocus while the field's text is unchanged. Coverage uses deferred work in the [routing picker](../tests/viewer_routing_pickers_js.test.mjs) and [browser state](../tests/browser_state_js.test.mjs) suites. |
| **Make browser build completion exact and terminal** | **False success or uncaught cancellation.** A valid checksum for an 18-byte output with a 19-byte recipe declaration returned `ok: true` and opened the output sink. The stream separately accepted a short producer `end` as `drained`. If the browser cancelled after the writer posted a chunk, delivery of that queued message called `enqueue` on a closed controller and threw `ERR_INVALID_STATE`. A delayed wake-lock grant after a fast failure could also leave the screen locked while idle. | Verify recipe length and source bounds before assembly, enforce the announced byte count at the stream boundary, and ignore late messages after retirement. The [worker and service-worker tests](../tests/sw_state_js.test.mjs) drive valid output, bad length, cancellation, and duplicate end. A [browser state test](../tests/browser_state_js.test.mjs) resolves a pending wake-lock request after the job ends. |
| **Isolate browser storage attempts** | **Lost build or stuck job.** Two tabs building the same download used the same private filename and metadata key. A new tab’s startup sweep could also delete an in-progress file after the worker closed its handle and before the page published readiness. A zero-byte storage write never advanced the worker’s loop. | Give each attempt a unique private name and metadata key. Hold the attempt lock from preparation through publication where Web Locks are available, and use it to arbitrate cleanup. A zero-progress write fails the job. [browser_state_js.test.mjs](../tests/browser_state_js.test.mjs) simulates overlapping attempts, orphan cleanup, and a zero-byte write. |

## Catalog, Drive, and online preview

| Drive picker ([index.html](../web/drive/index.html)), implicit | Idle or showing selection status | Pick a file or resolve preview URL | Validating. A cancelled picker returns to idle. URL resolution and validation errors surface in the picker. |
| Drive picker | Valid file | Enough browser storage estimated | Worker checks the file and returns a revision. The page commits the file and revision in one IndexedDB transaction, then asks the worker to reload that pick. A stale transaction fails when its starting revision differs. |
| Drive picker | Valid file or preview URL | Too little space for a file copy, or URL selection | `set-zim` validates and publishes either a session file or a persisted URL. The session path keeps the original file reference in memory. |
| Drive selection ([sw.js](../web/drive/sw.js)), implicit | Empty, persisted file, persisted URL, or session file | Validated set, page commit/reload, or clear | Publish the reader and record as one snapshot. Worker commits serialize. Worker picks compare the durable revision inside the commit transaction, so a page-side write can supersede a validating pick. A qualified reload checks its pick ID before invalidating the live snapshot. A failed worker mutation leaves the prior selection available. |
| Drive selection | Cold worker, or selection invalidated | First request or status | Lazy open shares one promise. A readable selection is served. An unreadable durable selection remains present and removable, and a later read can reopen it. Worker restart drops the session selection. |
| Drive selection | In-memory snapshot | Status checks a changed durable revision | Reopen the committed record. Status reports name, source, presence, and reader metadata from one snapshot. |
| Drive entry read ([sw.js](../web/drive/sw.js), [zim-reader.js](../web/drive/zim-reader.js)), implicit | Reader snapshot acquired | Shell path, missing entry, raw span, or buffered entry | Shell uses network then cache on fetch failure. A missing entry yields 404 or the designated absence marker. Large raw entries stream. A buffered read shares pending work only with the same reader and path. Settlement retires the pending entry. |
| Drive shell ([sw.js](../web/drive/sw.js)), explicit browser lifecycle | Installing | Precache attempted and worker activated | Claim clients and retire previous Drive cache generations. Asset failures are logged and install continues. |
| HTTP ZIM source / range proxy ([zim-reader.js](../web/drive/zim-reader.js), [ia-range-proxy.js](../preview-proxy/ia-range-proxy.js)), implicit | Unopened or uncached block | Open size probe or validated range request | Open source or pending block. Concurrent requests can reuse pending/cached blocks within the source. Successful reads expose the requested byte interval. Failed pending reads retire. Conflicting version evidence makes that source unusable until reopened. Upstream transient failures can yield a 503 from Drive, permanent upstream status a 502. Same-size remote replacements are detectable only when the response exposes comparable validators. |

## Further interleavings

| Machine | Interleaving reproduced or checked | Rule |
| --- | --- | --- |
| Drive selection | A page writes a file, another tab opens a session-only map, then the first tab sends its delayed reload. The old reload cleared the session reader even though it ultimately returned “superseded”. In the opposite direction, an older worker pick completing validation could overwrite a newer page-side write. | Reject stale reloads before changing the snapshot. Check the worker pick’s starting revision inside the write transaction. Both orderings have regression tests in [sw_state_js.test.mjs](../tests/sw_state_js.test.mjs). |
| Browser builds and storage | The builder returned its slot while asynchronous sink cleanup still owned resources. A second attempt starting in that window could have its UI reset by the first attempt’s finalizer. Invalid source or chunk sizes also made the assembly planner’s byte arithmetic unsafe. | Retain the job slot through cleanup. Validate source dimensions and check bytes written before closing the sink. The worker and browser-state suites cover those boundaries. |

## Verification

`node --test tests/browser_state_js.test.mjs tests/sw_state_js.test.mjs` runs deterministic search, storage, and worker interleavings. The Chromium [picker test](../tests/test_picker.mjs) delays a successful validation response until after Clear commits, then verifies that the old page cannot save over it. The [streaming test](../tests/test_sw_streaming.mjs) exercises real requests, including origin outage and recovery.

The CLI download regressions also ran against the original implementation. The inconsistent 206 published different bytes beginning at offset 5000, the same-size version swap completed without an error, and both invalid partial-file cases threw before clearing the partial. The fixed implementation passed the local HTTP and mocked-response tests. A synthetic ZIM built in Chromium from a network source and from a local file matched its expected checksum. A second network build forced through OPFS matched the same checksum after Save.

Drive has one current selection per browser origin. A request that already acquired a reader can finish against that reader while the selection changes. The service worker uses validators exposed by the origin to detect changed remote bytes. OPFS can reclaim an abandoned new attempt on startup when Web Locks are available. Browsers without Web Locks keep unfinished copies that failed cleanup so a startup sweep cannot remove another tab's work. Unfinished files under the older builders' names (not `job-…`) are removed at start-up when no build runs in the tab; a file still being written refuses removal.

The regression run passed the JavaScript suites, the CLI download and progress tests, the viewer build and copy checks, the Chrome Drive picker and streaming integrations, and the packaging integration with a freshly compiled Rust packer. The separate language-builder browser fixture failed during its pack setup on macOS because it uses Linux tooling, including GNU `stat` and `ionice`. The builder’s message protocol, byte-count gates, and storage transitions are covered by the deterministic tests above.
