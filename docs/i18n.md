# Viewer UI language

The map viewer (`index.html`) and the Find page (`places.html`) show their
buttons, panels, messages, Find chips, turn-by-turn instructions and place
sheet in the map's language: map-config.json `language`, which
`--language` sets ([languages.md](languages.md)). A map built with
`--language de` gets a German viewer. There are tables for German (reviewed
by a person), and Thai, Simplified Chinese, Spanish, French, Japanese,
Korean and Greek (machine-translated, and the viewer says so:
[below](#machine-translated-tables)). With a table, `<html lang>` is the
map language (or the table's `_lang`). A language without a table shows
English with no `lang`, and an English build is unchanged, character for
character.

Not translated, by design: place names, addresses, Wikipedia and Wikidata
text and other data (they are in the map's language already); licence
texts and product names in About (`translate="no"`); MapLibre's
"© OpenStreetMap contributors" attribution; technical details on the error
pages (user agent, URLs, the debug log); coordinates (always `47.37690,
8.54170`). Text the *build* writes is English in every build for now — the
Kiwix search pages, the article back bar and footer, a ZIM's default title
and description (part B2 of the bilingual design).

## How it works

- **English lives at the call site**: `szT('routing.no_route', 'No route
  found')`, `szT('find.none_in_map', 'No {chip} in this map', { chip: … })`,
  and for counts `szTn('place.links', n, { one: '{n} link', other: '{n}
  links' })`. Whole phrases with `{placeholders}`, never fragments glued
  together, because word order differs between languages. Keys are dotted
  lower-case. (`szT`, not `t`: the viewer has many local variables named
  `t`, and a shadowed `t()` would fail only at run time.)
- **Static markup** carries `data-i18n="key"` (its text),
  `data-i18n-title`, `data-i18n-placeholder`, `data-i18n-aria-label`. Text
  that code fills in is marked `data-i18n-code`; text that stays as written
  `translate="no"`.
- **The tables are inlined.** A published ZIM can never gain a file and an
  in-place viewer patch rewrites only the slots
  ([viewer-slots.md](viewer-slots.md)), so there is no i18n.json:
  `tools/build_i18n.py` writes the runtime and each page's own keys into
  part `005-i18n.html` and between the `SZ-I18N` markers in places.html.
  An existing German ZIM gets its German UI from an ordinary
  `patch_viewer_inplace.py`.
- **Chosen once map-config.json has loaded**: `szUseLanguage(config.language,
  location.search)` picks the table, translates the static markup in one
  pass, sets `<html lang>`, and fires `sz-ui-language` for code that
  rendered text earlier (the online-preview banner). What shows before that
  — "Loading places index…", an unsupported-browser page, a map-config that
  never loads — is English.
- **Numbers and dates** go through `szFixed(x, d)`, `szLocaleNum(x)`,
  `szCompactNum(n)` ("5,6 Mio."), `szMonthYear(y, m)` and `szDuration(min)`:
  `Intl` in the UI language, and in English exactly the old `toFixed` /
  `toLocaleString()` / month-name output. The arrival clock uses the UI
  language too ("14:05"). Units do not follow the language: the reader's
  choice or the device locale decides metric or imperial (`streetzim.units`,
  140-view-home-about.js).
- **Find chips** are translated by chip id (`szChipLabel`, `chip.food` …),
  whatever label the ZIM's manifest carries; in English the manifest's
  label shows as before. Inside a sentence English lower-cases it ("No food
  & drink in this map"), German keeps the noun ("Keine Treffer für „Essen &
  Trinken“ in dieser Karte").
- **Place types** (`fast_food`, `museum`, Overture's `italian_restaurant`)
  go through `szPlaceType`: the table's `type.<key>` when it has one
  (~270 common types in German; inlined as one `type` object), else the key with spaces, as English
  always showed it. `type.*` keys are the one family no call site names;
  the tests accept any of them in a table.
- **State is never read back from text.** "Current location" as a routing
  end is the token `SZ_HERE` plus a flag on the input; "My location" on the
  Find page is `data-sz-here`; the smoke gates read `data-*` attributes and
  chip ids (B0 of the design).

## Changing a string

1. Write it as `szT('area.what', 'English text', vars)` (or a `data-i18n*`
   attribute). The English must be a literal: the collector reads it.
2. `python tools/build_viewer.py`, then `bash scripts/sync-drive-viewer.sh`.
3. Add the translation to `resources/viewer/i18n/de.json`. The tests fail
   on a missing or stale key and on placeholders that differ from the
   English.

German style: formal "Sie" in full sentences (explanations, error
advice), the infinitive in short prompts and hints ("Start eingeben",
"Mindestens 2 Zeichen eingeben", "für mehr hineinzoomen"); standard
spelling with ß; terms that read right in Germany, Austria and
Switzerland (a first-level region is "Region", not "Bundesland").
Check a new string at 320 px: German runs ~40% longer, and buttons in
the navigation HUD and the Find page header have no room to spare.

Changing an English text under the same key leaves the German describing
the old one: give the string a new key when its meaning changes.

## Machine-translated tables

A table made by machine translation, not yet reviewed by a speaker, says so
on screen. It carries the table setting `"_machine": true`, and the
viewer then shows `common.machine_translated` ("Interface translated by
machine — corrections welcome", in that language) in About's first
section, under the map's title and build line, and in the Find page's
footer. The two notes are ordinary `data-i18n`
markup with `data-i18n-machine` and `style="display:none"`:
`szApplyI18n` shows them only when `szMachineTranslated()` is true, so
English, German and the pseudo-locale never do. When a person has reviewed
the table, delete `"_machine"` and the note goes away; there is nothing else
to change.

Table settings are keys that start with `_` (a UI key never does). They are
not text: `tools/build_i18n.py` accepts only the known ones, checks their
type and copies them into every page's table, and the key and placeholder
tests skip them.

| setting | what |
|---|---|
| `"_machine": true` | machine-translated: show the note |
| `"_lang": "zh-Hans"` | the BCP 47 tag for `<html lang>`, when the code alone does not say which script or glyphs to use. `zh.json` is Simplified Chinese; `zh-Hans` makes a device draw its Han characters with its Simplified Chinese font rather than a Japanese or Traditional one. Must start with the table's code. |
| `"_compact": "intl"` | large numbers in ten thousands, as Japanese, Korean and Chinese count them: from 10,000, `szCompactNum` and the Wiki list's population use Intl's compact notation in the UI language ("1.2万", "560만", "11亿"); below that, and where Intl has no compact notation, the number written out ("1,234"). The table's `num.*` (thousands, millions) are then unused. Set in `ja.json`, `ko.json`, `zh.json`. |

Thai and Chinese (2026-10, for the language-matrix prototype,
[language-matrix.md](language-matrix.md)) were translated by machine from
`en.json`, with the German as a guide to context, as a map app in that
language would say it. Style, for whoever reviews them:

- **Thai**: polite but impersonal; no ครับ/ค่ะ, no full stop at the end of a
  sentence (Thai has none; sentences are separated by a space). Map-app
  terms as Thai apps use them: เส้นทาง (directions), ขับรถ / เดิน / จักรยาน,
  ปั๊มน้ำมัน (gas), ที่พัก (the Hotels chip, which also holds motels and
  campsites), ร้านก๋วยเตี๋ยว for noodle shops. Thai has no plural:
  `other` only. Dates follow Thai `Intl`, which counts years in the
  Buddhist era ("กรกฎาคม 2569").
- **Chinese**: Simplified, mainland usage as in Amap / Baidu Maps:
  路线, 驾车 / 步行 / 骑行, 美食 / 酒店 / 景点 / 加油站 for the chips,
  “…” quotes and full-width punctuation (，：（）——) around Chinese text, a
  space between Chinese and a Latin word or number ("3D 地形", "{n} 个地点").
  `other` only. `zh.json` is Simplified; a request for `zh-TW` or
  `zh-Hant` (`?uilang=`) gets it too, as `--language` codes carry no
  script. Large numbers in 万 / 亿 (`_compact`, above).

Spanish, French, Japanese, Korean and Greek (2026-10-14, the California
menu's other languages) were made the same way:

- **Spanish**: neutral international Spanish, "tú" in prompts as Spanish
  map apps write them; Cómo llegar, En coche / A pie / En bici, gasolinera.
  one/other.
- **French**: "vous" in sentences, the infinitive in short prompts; a space
  before ":" and "?", « » around a quoted name; Itinéraire, En voiture /
  À pied / À vélo; "Wikipédia". one/other (`many` falls back to `other`).
- **Japanese**: です/ます in sentences, nouns on buttons; 経路 / ルート,
  車 / 徒歩 / 自転車, ガソリンスタンド; 「」 quotes. `other` only; 万 / 億.
- **Korean**: 합니다 / 하세요 in sentences; 길찾기, 자동차 / 도보 / 자전거, 주유소;
  no particle right after a placeholder (it would depend on the word).
  `other` only; 만 / 억.
- **Greek**: polite plural; the question mark is ";" (so English ";"
  became "·"), « » quotes; Οδηγίες, Αυτοκίνητο / Με τα πόδια / Ποδήλατο.
  The navigation HUD's end button is "Διακοπή": longer words leave the
  distance no room at 320 px (the CI check above). one/other.

All of them:

- keep, as German does, product and source names (StreetZim, Kiwix,
  OpenStreetMap, OSM, Wikipedia (French: Wikipédia), MapLibre), units ("m",
  "km": they follow the reader's unit choice, not the language) and
  `{placeholders}`;
- are drawn in the device's own fonts (`--ui-font` is a system stack);
  every phone and desktop has Thai, CJK and Greek fonts. Thai stacks vowels
  and tone marks above and below the line, so check new short labels in
  fixed-height buttons;
- name languages through `Intl.DisplayNames` in the UI language (the Wiki
  list's language tags, "Read full article in English"), so a phrase
  around `{language}` must take the language's name as Intl gives it
  (French "anglais", Spanish "inglés", Greek "Αγγλικά").

## Known limits of the checks

The lint in `tests/test_viewer_i18n.py` is best effort. It sees English
that goes straight into a text sink (`textContent`, `innerHTML`, `title`,
`placeholder`, `value`, plain or `+=`; `createTextNode`, `setAttribute`
of aria-label/title/placeholder/alt, the viewer's own status and toast
helpers), or that sits in a variable or table used directly in one. It
does not follow text through function arguments, object properties set
elsewhere, string building across statements, or a helper it does not
know. The browser pseudo-locale check (`tools/i18n_pseudo_check.mjs`) is
the backstop, and it only sees the states it visits: a failure state the
test map cannot produce is skipped with the reason, and in rows that join
a label with data ("[restaurant] · Ville Haute") a part without any
bracket is taken as data, so an untranslated word there passes.

## Pseudo-locale and the URL override

`?uilang=qps` shows every translated string as `[text]`: anything on screen
without brackets that is not data was missed. `?uilang=de` shows a map in
German whatever its `language` — for checking the translation on an English
or French test ZIM. Neither is remembered. The smoke gates take
`SMOKE_UILANG=qps` (or `de`) to run the same checks on a translated viewer.

## Adding a language

Copy `de.json` to `<code>.json` (ISO 639-1, the code `--language` takes),
translate every value and keep every `{placeholder}`. Counts need the
language's plural categories (`Intl.PluralRules`: one/other for German,
one/few/many/other for Polish, other alone for Thai and Chinese); add the
language to `PLURAL_FORMS` in `tests/test_viewer_i18n.py`. A machine
translation gets `"_machine": true` (and the language goes into `MACHINE`
there), and the PWA's article bar needs its words (`BACK_TO_MAP` in
`web/drive/sw.js`; `tests/sw_back_bar_js.test.mjs` asks for one per table).
Rebuild; each page grows by about the size of its table (German: ~20 KB in
index.html, ~11 KB in places.html; Thai, three bytes a letter in UTF-8:
~34 KB and ~18 KB; Chinese: ~19 KB and ~10 KB; Spanish, French, Japanese,
Korean, Greek: ~24 KB and ~12 KB each).

**The slots are nearly full.** With these nine tables index.html is
~693 KB of its 1 MB slot and places.html ~227 KB of its 256 KB
([viewer-slots.md](viewer-slots.md)). `tests/test_rtl_text_plugin.py`
wants index.html under 2/3 of its slot (~699 KB), so the next table does
not fit as things are: it needs a smaller encoding of the tables (they
repeat the 273 place types in both pages) or larger slots, which every
published ZIM can only get from a full re-pack.
